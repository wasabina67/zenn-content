- 開発現場において「ソースコードの履歴を管理する」という行為は、今や空気のように当たり前の存在です。
- しかし、現代の標準である Git に至るまでには、先人たちが直面した不便さを解消するための技術革新の積み重ねがありました。
- 本記事では、バージョン管理システム（VCS）の代表的な3つのツールを軸に、その進化の歴史を振り返ります。

## 1. CVS (Concurrent Versions System)
**〜共同開発の幕開け〜**

1990年頃に登場した CVS は、それまで個人のローカル環境で「ファイル名に日付をつけて保存する」といった原始的な管理をしていた開発現場に革命をもたらしました。

- 中央集権型の確立: 1台の中央サーバーにリポジトリを置き、開発者はそこからチェックアウトして作業する、というモデルを普及させた。
- 並行編集（マージベース）: ファイルロック方式に代わる選択肢として、複数人が同じファイルを同時に編集し、後でマージする方式を広めた。
- 課題: コミットがアトミックでなく（途中で失敗するとリポジトリが壊れる）、ディレクトリやファイルのリネームも追跡できなかった。

## 2. Subversion (SVN)
**〜信頼性と安定性の向上〜**

2000年頃、CVS の決定的な弱点を克服するために登場したのが Subversion（SVN）です。「CVS よりも優れた CVS」を目指して設計されました。

- アトミックなコミット: 複数ファイルの変更が「全て成功」か「全て失敗」のいずれかになり、リポジトリの整合性が保たれるようになった。
- ディレクトリ・リネームの追跡: ファイルやディレクトリの移動・改名を履歴として正しく追跡できるようになった。
- リポジトリ全体のリビジョン番号: コミットごとにリポジトリ全体で一意な連番（r1, r2, ...）が付与され、状態の特定が容易になった。
- 課題: 中央サーバーへの依存が強く（オフラインでは履歴参照やコミット不可）、ブランチ作成やマージの動作も重かった。

## 3. Git
**〜分散型による自由と高速化〜**

2005年、Linuxカーネルの開発者であるリーナス・トーバルズ氏によって開発された Git は、それまでの「中央集権型」の常識を覆しました。

- 分散型モデル: 各開発者が完全なリポジトリのコピーを持つため、オフラインでもコミットや履歴参照が可能になった。
- 軽量・高速なブランチ: ブランチが単なるコミットへのポインタとして実装され、作成・切り替え・マージが一瞬で行えるようになった。
- SHA-1 によるコンテンツ管理: ファイルやコミットを内容のハッシュ値で識別する「コンテンツアドレス方式」により、重複排除と整合性検証を両立した。

## 4. まとめ

- CVS は「共同開発」という文化を、SVN は「信頼性」を、そして Git は「自由と速度」を VCS にもたらしました。
- 各ツールの進化は、単なる機能追加ではなく、前世代が抱えていた課題への明確な回答として生まれています。
- 普段何気なく使っている `git commit` や `git branch` も、こうした歴史の積み重ねの上に成り立っていると知ると、より味わい深く感じられるはずです。
